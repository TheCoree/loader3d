# Виджет Loader3D для iPhone (Scriptable)

Виджет для владельца сайта. Показывает, работает ли сайт (API отвечает, база доступна) и как он нагружен, сколько
пользователей сейчас онлайн, выручку и регистрации за неделю с графиком по дням. Работает на домашнем экране
(маленький, средний, большой, на iPad — очень большой) и на экране блокировки (круг, прямоугольник, строка).
Нажатие на виджет открывает админ-панель.

Скрипт — [loader3d-widget.js](loader3d-widget.js), данные — `GET /api/widget/stats` (`backend/app/widget.py`).

## 1. Включить на сервере

1. Сгенерировать ключ — лучше на своём компьютере, тогда сам ключ на сервер вообще не попадёт:
   ```bash
   cd backend && uv run python -m app widget-key      # или: backend/.venv/Scripts/python -m app widget-key
   ```
   На сервере тоже можно: `docker compose exec api python -m app widget-key`. Команда печатает ключ `l3dw_…`
   (показывается один раз, нигде не сохраняется) и строку для `.env`: `WIDGET_KEY_SHA256=…` — это SHA-256 ключа.
2. Добавить эту строку в `.env` на сервере (`/opt/loader3d/.env`). Для нескольких устройств — свой ключ на каждое,
   хэши через запятую: `WIDGET_KEY_SHA256=хэш1,хэш2`.
3. Применить: `docker compose up -d api` (после обновления кода — `git pull && docker compose up -d --build`).
   `docker compose restart` новые переменные **не** подхватывает.
4. Проверить, что эндпоинт включён: `curl -s -o /dev/null -w '%{http_code}\n' https://<домен>/api/widget/stats`
   → `401` (включён, без ключа не пускает). `404` — переменная не подхватилась или значение пустое.

Ключ на телефон передавайте через AirDrop самому себе, общий буфер обмена Mac → iPhone или Заметки — не через
мессенджеры и почту. Если в буфере обмена лежит ключ, скрипт подставит его сам и после сохранения очистит буфер.

## 2. Установить на iPhone

1. Установить [Scriptable](https://apps.apple.com/app/scriptable/id1405459188) (бесплатно).
2. Открыть [loader3d-widget.js](loader3d-widget.js) на GitHub → «Raw» → скопировать весь текст. В Scriptable: «+»,
   вставить, назвать скрипт «Loader3D». Другой путь — положить файл в папку iCloud Drive → Scriptable.
3. Запустить скрипт в приложении (▶). При первом запуске он спросит адрес сайта (`https://ваш-домен`) и ключ,
   проверит подключение и сохранит их в связке ключей iOS. Потом при запуске — меню: предпросмотр любого размера,
   проверка подключения, смена адреса или ключа, удаление ключа.
4. Домашний экран: долгое нажатие → «Править» → «Добавить виджет» → Scriptable → размер. Нажать на добавленный
   виджет: Script — «Loader3D», Parameter — вид из таблицы ниже (пусто — обзор).
5. Экран блокировки: долгое нажатие на экран блокировки → «Настроить» → экран блокировки → поле виджетов →
   Scriptable → круг или прямоугольник (или поле над часами — строка). Так же выбрать скрипт и параметр.

| Параметр | Что показывает |
|---|---|
| пусто, `overview`, `обзор` | Статус, онлайн, выручка и регистрации за 7 дней, график по дням |
| `revenue`, `выручка` | Выручка за 7 дней, сравнение с прошлой неделей, график |
| `signups`, `регистрации` | Новые пользователи за 7 дней, сравнение, график |
| `online`, `онлайн` | Пользователи и гости на сайте сейчас |
| `load`, `нагрузка` | Запросы к API в минуту за последние 30 минут, время ответа, база, CPU, память, диск |
| `status`, `статус` | Крупно — работает ли сайт, и почему нет |

Большой виджет показывает всё сразу; параметр там решает, какие графики крупнее.

## Что значат статусы

| Статус | Значит |
|---|---|
| Работает | API отвечает, база доступна, проблем не видно |
| Сайт не отвечает | Сервер не ответил за 12 секунд или Caddy ответил 502/503/504 (API лежит) |
| Нет интернета | Не отвечает ни сайт, ни apple.com — дело в телефоне, сайт не проверен |
| База недоступна | API работает, но база не ответила за 5 секунд; цифры — последние известные |
| База отвечает медленно | `SELECT 1` дольше 500 мс |
| Ошибки на сервере | За последние 15 минут были ответы 5xx (число за час — внизу большого виджета) |
| Сайт отвечает медленно | p95 за 5 минут больше 2 секунд: каждый двадцатый запрос (из 20+) ждёт дольше |
| Высокая нагрузка / Мало памяти / Мало места на диске | Load average больше числа ядер / память или диск заняты больше чем на 90% |
| Неверный ключ | Сервер не принял ключ: откройте скрипт и введите ключ заново |
| Виджет выключен | На сервере нет `WIDGET_KEY_SHA256` (или адрес не того сайта) |

Если сайт не ответил, виджет показывает последние полученные цифры с пометкой «данные от 14:05» (оранжевым).

**Онлайн** — вошедшие пользователи, от которых был запрос за последние 5 минут, и гости — посетители публичных
страниц за 5 минут (то же, что «Сейчас на сайте» во вкладке «Посещаемость»). **Выручка** — оплаченные платежи по дате
оплаты; пока онлайн-оплата не включена, там 0 ₽ и подпись «оплата не подключена». Дни — по московскому времени,
как в админ-панели. **Нагрузка** — запросы к API (без проверок Docker и самого виджета), CPU — load average на ядро
сервера; на сервере не Linux этих цифр нет («—»).

## Обновление

Когда обновлять виджет, решает iOS: обычно раз в 15–30 минут, за день — несколько десятков раз. Скрипт просит
обновление через 15 минут, а при проблеме — через 5. Чтобы увидеть цифры сразу, откройте Scriptable или нажмите
«Проверить подключение» в меню скрипта.

## Отозвать ключ

Удалить его хэш из `WIDGET_KEY_SHA256` на сервере и выполнить `docker compose up -d api` — ключ перестаёт работать
сразу. На телефоне: запустить скрипт → «Удалить ключ и кеш». Потеряли телефон — сначала отзовите ключ на сервере.

## Безопасность

- Ключ — 256 случайных бит. Сервер хранит только его SHA-256: копия `.env` или бэкапа не даёт доступа к виджету.
  Сравнение — `hmac.compare_digest` за одинаковое время.
- Ключ передаётся только в заголовке `Authorization: Bearer`, никогда в адресе (адреса попадают в логи). Скрипт
  принимает только `https://` (обычный `http` — лишь для компьютера в локальной сети) и не идёт по перенаправлениям,
  чтобы ключ не ушёл на другой адрес.
- Без `WIDGET_KEY_SHA256` маршрута нет совсем — ответ 404, как на любой несуществующий адрес.
- Лимиты: 30 запросов в минуту с одного IP; после 10 неверных ключей за 15 минут этот IP получает 429 даже с верным
  ключом. Неверные попытки пишутся в лог API (IP, без ключа).
- В ответе только агрегаты: ни email, ни имён, ни id, ни IP. Ответ не кешируется (`Cache-Control: no-store`).
- На телефоне адрес и ключ — в связке ключей iOS, не в тексте скрипта (скрипт можно показывать и синхронизировать
  через iCloud без опаски). Последний ответ кешируется в папке Library приложения Scriptable — не в iCloud и не в
  «Файлах»; ключа в нём нет.
- Отдельный ключ, а не токен админа: access-токен живёт 15 минут, а refresh-токен открывает весь аккаунт. Ключ
  виджета умеет только читать эту сводку.

## Разработка

- `node tools/scriptable/preview/check.mjs` — запускает скрипт в эмуляторе API Scriptable
  ([preview/scriptable-shim.js](preview/scriptable-shim.js)) во всех размерах, видах и ситуациях
  ([preview/mock.js](preview/mock.js)) и проверяет результат: без ошибок, без «undefined» на экране, ключ только в
  заголовке, верные статусы, кеш. С `LOADER3D_URL` и `LOADER3D_WIDGET_KEY_FILE` — ещё и с живым API.
- Превью в браузере: `npm run dev` и http://localhost:5173/tools/scriptable/preview/index.html — все размеры и виды,
  светлая и тёмная тема, ситуации из `mock.js`. «Показать с API» — с запущенным локально API (ключ вводится на
  странице и хранится только в её памяти). Шрифты и значки SF Symbols там приблизительные.
