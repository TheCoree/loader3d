# Loader3D — интерактивное 3D-планирование загрузки фуры

Веб-приложение для раскладки грузов в кузове фуры/сцепки: полупрозрачный кузов с размерными линиями,
док (зона накопления) у задних дверей, перетаскивание грузов мышью и пальцем с гравитацией, коллизиями
и магнитной привязкой. В одной схеме может быть несколько машин, грузы можно кантовать, а загораживающие
обзор грузы — делать прозрачными.

Стек: **React 19 + TypeScript + three.js + zustand**, интерфейс — **Tailwind CSS 4 + shadcn/ui** (Radix,
иконки lucide), маршруты — React Router, запросы — TanStack Query; сборка — Vite, тесты — Vitest.
Бэкенд ([backend/](backend)): **Python 3.14 + FastAPI + SQLAlchemy 2 (async)**, SQLite в разработке, Postgres в проде.

```bash
npm install
npm run dev        # http://localhost:5173 (нужен запущенный бэкенд — см. «Бэкенд»)
npm test           # юнит-тесты ядра (коллизии, гравитация, магниты, перемещение стопок)
npm run build      # проверка типов + production-сборка в dist/ + пререндер лендинга (scripts/prerender.mjs)
npm run preview    # production-сборка на http://localhost:4173 (как в проде: лендинг из готового HTML)
```

Для работы в браузере запускаются оба процесса: `cd backend && uv run python -m app --reload` и
`npm run dev`; Vite проксирует `/api` на бэкенд. Вход, регистрация и схемы — через API.
Проще одной командой: **`./dev.sh`** (Linux, macOS, Git Bash; Ctrl+C останавливает оба) или **`dev.bat`**
(Windows: двойной клик — API в отдельном окне, сайт в текущем). Оба ставят `node_modules` при первом запуске,
берут `uv` или уже созданный `backend/.venv` и открывают http://localhost:5173.

## Деплой (Docker)

На сервере нужны только Docker и Docker Compose v2 — Node.js и Python не нужны, сборка идёт внутри
образов (с прогоном тестов). Три контейнера:

- `web` — [Caddy](https://caddyserver.com): статика фронтенда, HTTPS, проксирует `/api/*` в `api`;
- `api` — бэкенд, при старте сам применяет миграции БД;
- `db` — Postgres, наружу не публикуется, данные в томе `postgres_data`;
- `mail` — по желанию, своя почта (`COMPOSE_PROFILES=mail`, см. «Своя почта» ниже).

```bash
git clone https://github.com/TheCoree/loader3d.git && cd loader3d
cp .env.example .env     # задать JWT_SECRET и POSTGRES_PASSWORD (openssl rand -hex 32), остальное по желанию
docker compose up -d
```

Доступ к админ-панели (`/admin`) — у аккаунта с правами администратора. Выдать права существующему
аккаунту: `docker compose exec api python -m app make-admin you@example.com` (`--revoke` — забрать).
Проверить почту (`MAIL_BACKEND=smtp`): `docker compose exec api python -m app send-test-mail you@example.com`.
Виджет сайта на iPhone (статус, нагрузка, онлайн, выручка и регистрации) — [tools/scriptable](tools/scriptable/README.md):
ключ — `python -m app widget-key`, его хэш — в `WIDGET_KEY_SHA256`.

Обновление: `git pull && docker compose up -d --build`. Логи: `docker compose logs -f`.
Если сервер развёрнут до появления бэкенда — перед обновлением добавить в `.env` новые переменные
из `.env.example` (без `JWT_SECRET` и `POSTGRES_PASSWORD` compose не запустится).

Резервная копия БД: `docker compose exec db pg_dump -U loader3d loader3d > backup.sql`,
восстановление: `docker compose exec -T db psql -U loader3d loader3d < backup.sql`.

Типовые варианты:

- **Отдельный сервер с доменом** — DNS-запись домена указывает на сервер, порты 80 и 443 открыты:
  `SITE_ADDRESS=loader.example.com`. Сертификат выпускается и продлевается сам и хранится в томе
  `caddy_data` (его не удалять, иначе выпуск начнётся заново).
- **За существующим nginx/traefik** — `SITE_ADDRESS=:80`, `HTTP_PORT=127.0.0.1:8080`,
  `HTTPS_PORT=127.0.0.1:8443`, а во внешнем прокси — `proxy_pass http://127.0.0.1:8080`.
- **Просто по IP** — значения по умолчанию, приложение откроется на `http://<IP сервера>/`.

Схемы и настройки отображения хранятся в аккаунте на сервере. План, который остался в браузере от версии
без аккаунтов, страница «Мои схемы» предлагает сохранить как схему; настройки из браузера переезжают в
аккаунт при первом входе.

### Своя почта

Сервис `mail` ([docker-mailserver](https://docker-mailserver.github.io/docker-mailserver/latest/)) —
почтовый сервер на том же сервере: ящики домена (IMAP) и отправка кодов без почтового сервиса. Rspamd
фильтрует спам и подписывает письма DKIM, fail2ban закрывает подбор паролей. TLS — сертификат, который
Caddy получает для `MAIL_HOSTNAME`; продления подхватываются сами. Нужны открытые порты 25, 465, 587, 993
и чтобы хостер не закрывал исходящий 25.

1. DNS (на примере `example.com`, сервер `203.0.113.10`): A `mail` → `203.0.113.10`; MX `@` →
   `mail.example.com` (приоритет 10); TXT `@` → `v=spf1 mx -all`; TXT `_dmarc` →
   `v=DMARC1; p=none; rua=mailto:postmaster@example.com`; DKIM — после шага 3.
2. PTR (обратная запись IP) — в панели хостера: `203.0.113.10` → `mail.example.com`. Без неё Gmail и
   Mail.ru отклоняют письма или кладут их в спам.
3. В `.env`: `COMPOSE_PROFILES=mail`, `MAIL_HOSTNAME=mail.example.com`, имя добавить в `REDIRECT_ADDRESS`,
   `docker compose up -d --build`. Когда Caddy получит сертификат для `mail.example.com`:
   ```bash
   docker compose exec mail setup email add noreply@example.com 'ПАРОЛЬ'   # ящик, от которого уходят коды
   docker compose exec mail setup email add you@example.com                # свой ящик (спросит пароль)
   docker compose exec mail setup alias add postmaster@example.com you@example.com
   docker compose exec mail setup config dkim domain example.com
   docker compose exec mail cat /tmp/docker-mailserver/rspamd/dkim/example.com-mail.public.dns.txt
   ```
   Последняя команда печатает DKIM — TXT-запись `mail._domainkey`. После `setup config dkim` —
   `docker compose restart mail`.
4. Коды через свою почту: `MAIL_BACKEND=smtp`, `MAIL_FROM="Loader3D <noreply@example.com>"`,
   `SMTP_HOST=mail.example.com` (внутри compose имя ведёт прямо в контейнер `mail`), `SMTP_PORT=465`,
   `SMTP_SECURITY=ssl`, `SMTP_USERNAME=noreply@example.com`, `SMTP_PASSWORD` — пароль ящика;
   `docker compose up -d api` и `docker compose exec api python -m app send-test-mail you@example.com`.

Почтовый клиент: IMAP `mail.example.com:993` (SSL), SMTP `mail.example.com:465` (SSL), логин — адрес
целиком. Репутация нового IP поначалу низкая: проверьте письмо на mail-tester.com и не включайте
`p=quarantine` в DMARC, пока не убедитесь, что SPF и DKIM проходят.

### Поисковики и превью ссылок

Главная (`/`) — лендинг. `npm run build` после сборки рендерит его в `dist/index.html` настоящим HTML
(`scripts/prerender.mjs` → `src/prerender.tsx`, браузер его гидрирует): заголовки, тексты, тарифы и FAQ
видны поисковикам без JavaScript; там же мета-теги, Open Graph (`public/landing/og.jpg`), JSON-LD
(`SoftwareApplication` с ценами и `FAQPage`), `robots.txt`, а с `SITE_URL` — canonical и `sitemap.xml`.
Так же рендерятся **калькуляторы** (`/kalkulyator` и `/kalkulyator/…`, см. «Что умеет»): каждый — в свой файл
`dist/kalkulyator/<имя>.html` со своими title, description, canonical и JSON-LD (`WebApplication`, `FAQPage`,
`BreadcrumbList`); Caddy отдаёт `{path}.html`, адреса со слешем на конце переадресует без него.
Остальные маршруты приложения Caddy отдаёт из пустой оболочки `dist/app.html`. Права в Яндекс.Вебмастере и Google
Search Console подтверждаются мета-тегом из `YANDEX_VERIFICATION` / `GOOGLE_SITE_VERIFICATION` или DNS-записью;
список страниц с запросами для Вордстата и что сделать в обоих сервисах — [docs/seo.md](docs/seo.md).

## Бэкенд (API)

Каталог [backend/](backend): FastAPI, SQLAlchemy 2 (async), Alembic, Pydantic. Всё под префиксом `/api`,
интерактивная документация — `/api/docs`, схема OpenAPI — `/api/openapi.json` (только при
`ENVIRONMENT=development`; в проде они выключены) (из неё можно генерировать
TS-типы клиента). Поля JSON — в camelCase, как во фронтенде.

Локально нужен [uv](https://docs.astral.sh/uv/) (`pip install uv` или установщик с сайта), Python 3.14 uv
найдёт или скачает сам:

```bash
cd backend
uv sync                          # зависимости в backend/.venv
uv run python -m app --reload    # миграции + сервер на http://127.0.0.1:8000 (SQLite: backend/loader3d.db)
uv run pytest                    # тесты (на временной SQLite; TEST_DATABASE_URL=postgresql+asyncpg://… — на Postgres)
uv run ruff check . && uv run ruff format --check .
```

`npm run dev` проксирует `/api` на `127.0.0.1:8000`, поэтому фронтенд в разработке ходит в API с того
же адреса, что и в проде. Настройки бэкенда — переменные окружения, `.env` в корне репозитория (тот же, что
для деплоя) или `backend/.env` (важнее корневого): `DATABASE_URL`, `DATABASE_PASSWORD`, `JWT_SECRET`,
`ACCESS_TOKEN_TTL_MINUTES`, `REFRESH_TOKEN_TTL_DAYS`, `REGISTRATION_OPEN`, `EMAIL_VERIFICATION`, `MAIL_BACKEND`,
`MAIL_FROM`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURITY`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SITE_URL`,
`FORWARDED_ALLOW_IPS` (без него — `127.0.0.1`), `TIERS_ENABLED`, `PAYMENT_PROVIDER`, `CISPAY_SHOP_ID`,
`CISPAY_API_KEY`, `CISPAY_SANDBOX` (только разработка: платежи песочницы cisPay считаются оплаченными), `WIDGET_KEY_SHA256`, `CORS_ORIGINS`,
`ENVIRONMENT` (см. [config.py](backend/app/config.py)). `TIERS_ENABLED` из корневого `.env` читает и Vite —
после его смены перезапустите оба процесса.

Изменили модели в `app/models.py` — нужна миграция, которая работает и на SQLite, и на Postgres:
`uv run alembic revision --autogenerate -m "что изменилось"`, проверить файл в `migrations/versions/`.
Тест `test_migrations_match_the_models` падает, если миграции не совпадают с моделями.

### Эндпоинты

| Метод и путь | Что делает |
|---|---|
| `POST /api/auth/register` | Регистрация `{email, password, displayName?}` → вход (как login) |
| `POST /api/auth/login` | `{email, password}` → `{accessToken, expiresIn, user}` + cookie с refresh-токеном |
| `POST /api/auth/password/forgot` | `{email}` → код сброса на почту (ответ одинаковый, есть аккаунт или нет) → `{retryAfter}` |
| `POST /api/auth/password/reset` | `{email, code, password}` → новый пароль, все сессии завершены, вход (как login) |
| `POST /api/auth/refresh` | По cookie: новый access-токен, refresh-токен ротируется |
| `POST /api/auth/logout` | Завершить текущую сессию (нужна только cookie) |
| `GET /api/auth/sessions` | Активные сессии (устройства): user agent, IP, последняя активность, `current` |
| `DELETE /api/auth/sessions/{id}` / `DELETE /api/auth/sessions` | Завершить одну / все остальные сессии |
| `GET /api/users/me`, `PATCH /api/users/me` | Профиль (`isAdmin`, `settings`, `subscription` — тариф, срок, лимиты), смена `displayName` |
| `PATCH /api/users/me/settings` | Настройки отображения редактора (только изменённые поля), общие для всех устройств |
| `POST /api/users/me/trial` | Пробный период «Pro» (один раз на аккаунт) |
| `GET /api/users/me/usage` | С тарифами: сколько лимитов использовано — схем, машин и грузов в самой большой схеме, схем сверх лимитов (`{plans, maxVehicles, maxItems, overLimit}`) |
| `POST /api/users/me/password/code` | Письмо с кодом для смены пароля (раз в минуту, не больше 5 писем с кодами в час) |
| `POST /api/users/me/password` | Смена пароля `{code, newPassword}` — только по коду из письма, текущий пароль не принимается; остальные сессии завершаются |
| `POST /api/users/me/delete/code` | Письмо с кодом для удаления аккаунта |
| `DELETE /api/users/me` | Удаление аккаунта со всеми схемами — по коду из письма (`{code}` в теле) |
| `GET /api/plans?q=&sort=-updatedAt&limit=20&offset=0` | Главная: схемы пользователя без содержимого (`vehicleCount`, `bodyCount`, `itemCount`, даты), поиск по названию, `sort`: `updatedAt`/`createdAt`/`name`, `-` — по убыванию |
| `POST /api/plans` | Новая схема `{name, data?}`; без `data` — пустая с еврофурой 13,6 м |
| `GET /api/plans/{id}` | Схема целиком: `data` — тот же `Plan`, что экспортирует фронтенд в JSON |
| `PATCH /api/plans/{id}` | Сохранить `{version, name?, data?}`; `409 version_conflict`, если схему уже изменили |
| `POST /api/plans/{id}/duplicate` | Копия `{name?}` (по умолчанию «… (копия)») |
| `PUT /api/plans/{id}/thumbnail` | Превью для карточки: тело — JPEG/PNG/WebP до 512 КБ; рисует редактор, версию схемы не меняет |
| `GET /api/plans/{id}/thumbnail?v=` | Превью (`thumbnailAt` в списке схем; `null` — ещё нет) |
| `DELETE /api/plans/{id}` | Удалить |
| `POST /api/leads` | Заявка с сайта или из окна смены тарифа `{name, email?, phone?, company?, message?, tier?}` (без входа) |
| `GET /api/admin/stats` | Админ: пользователи, активность, тарифы, схемы, новые заявки |
| `GET /api/admin/users?q=&tier=&status=&sort=&limit=&offset=` | Админ: пользователи с тарифом, числом схем, сессий и последней активностью |
| `POST /api/admin/users`, `PATCH /api/admin/users/{id}` | Админ: создать аккаунт; имя, блокировка (`isActive`, сессии завершаются), права (`isAdmin`) |
| `PUT /api/admin/users/{id}/subscription` | Админ: тариф, срок, пробный период, лимиты «Индивидуального», заметка |
| `POST /api/admin/users/{id}/password`, `DELETE …/sessions`, `DELETE /api/admin/users/{id}` | Админ: новый пароль, выход везде, удаление |
| `GET /api/admin/leads`, `PATCH/DELETE /api/admin/leads/{id}` | Админ: заявки, отметка «обработана», удаление |
| `GET /api/billing` | Без входа: можно ли оплатить онлайн и цены, которые списываются |
| `POST /api/billing/checkout` | `{period: "month" \| "year"}` → платёж «Pro» и `paymentUrl` страницы оплаты (нужен подтверждённый email) |
| `GET /api/billing/payments`, `GET /api/billing/payments/{id}` | Платежи аккаунта; страница возврата опрашивает свой платёж (ожидающий API заодно сверяет с провайдером, не чаще раза в 5 с) |
| `POST /api/billing/cispay/webhook` | Уведомление cisPay о статусе платежа; без верной подписи `X-Signature` — 401 |
| `GET /api/admin/payments` | Админ: платежи (`?status=paid\|pending\|canceled`) и сумма полученного |
| `POST /api/analytics/collect` | Без входа: отчёт страницы о визите (страницы, время в разделах лендинга, клики, регистрация) — `navigator.sendBeacon` |
| `GET /api/admin/analytics?days=7\|30\|90` | Админ: посещаемость за период и сравнение с прошлым |
| `GET /api/health` | Проверка живости и связи с БД |
| `GET /api/widget/stats` | Виджет владельца ([tools/scriptable](tools/scriptable/README.md)), только с `WIDGET_KEY_SHA256`: ключ в `Authorization: Bearer`; статус и проблемы, нагрузка (запросы в минуту, p95, 5xx, время БД, CPU/память/диск), онлайн, выручка, регистрации и посетители по дням за 14 дней — только агрегаты. 30 запросов в минуту с IP, 10 неверных ключей за 15 минут → 429 |

Ошибки: `{"detail": {"code": "...", "message": "..."}}` — `code` для логики клиента, `message` по-русски
для показа; ошибки валидации — стандартный ответ FastAPI `422`.

### Как клиенту работать с сессией

- **Access-токен** (JWT, 15 мин) — из ответа login/register/refresh, держать в памяти (не в localStorage)
  и слать в `Authorization: Bearer …`.
- **Refresh-токен** (JWT, 30 дней) — только в httpOnly-cookie `loader3d_refresh` с `Path=/api/auth` и
  `SameSite=Strict` (и `Secure`, если сайт открыт по HTTPS — по голому HTTP браузер такую cookie
  выбросил бы): JavaScript её не видит, браузер шлёт её только на `/api/auth/*`.
- При загрузке страницы — `POST /api/auth/refresh`: 200 → пользователь вошёл, 401 → показать вход.
- На `401` с `code: "token_expired"` — один раз `refresh` и повторить запрос; если и refresh дал 401 —
  на экран входа.
- Refresh выдаёт новый refresh-токен (не чаще раза в 30 секунд: повторный refresh в эти 30 секунд
  получает тот же). Старый принимается ещё 30 секунд (несколько вкладок обновляются одновременно),
  позже — считается украденным, и сессия завершается для всех её копий.
- Logout и «завершить сессию» действуют сразу: каждый запрос проверяет, что сессия жива.
- Сброс забытого пароля — `password/forgot` (код на почту, живёт 15 минут, новый — не чаще раза в минуту,
  5 неверных попыток сжигают код), затем `password/reset`: новый пароль, все сессии завершены, вход.
- Лимиты (`backend/app/ratelimit.py`, в памяти процесса API): 10 неверных паролей к аккаунту и 50 с одного IP
  за 15 минут, 10 регистраций и 10 запросов кода сброса с IP в час, 20 неверных кодов сброса с IP за 15 минут,
  5 заявок с IP за 10 минут. Превышение — `429` с `Retry-After` и `retryAfter` в `detail`.
- Сохранение схемы — `PATCH` с `version` из последнего ответа; на `409` предложить перезагрузить схему.

Сервер проверяет структуру и диапазоны плана (размеры как в `core/presets.ts` и `core/item.ts`, вес груза
до 30 т и грузоподъёмность до 60 т — оба поля необязательны, до 10 машин по 1–3 кузова, до 5000 грузов,
уникальные id), но не физику: отсутствие пересечений по-прежнему обеспечивает `settle()` на клиенте.
План — `{vehicles, dockMode, items, nextSeq}`; схемы, сохранённые до появления нескольких машин (`bodies` вместо
`vehicles`), читаются как одна машина «Машина 1» — так же, как `parsePlan()` на клиенте.

- **Оплата «Pro»** (`backend/app/billing.py`, с `PAYMENT_PROVIDER`): на «Тариф и оплата» и в окне апгрейда — «на месяц»
  (1 990 ₽) или «на год» (19 080 ₽); сервер создаёт платёж по своим ценам (`PRICES`, те же числа — в
  `src/lib/tiers.ts`), покупатель платит на странице провайдера и возвращается в `/billing?payment=…`, где
  страница ждёт подтверждения (старый адрес `/account?payment=…` переадресуется туда же). Оплата продлевает «Pro» на календарные месяцы — от конца текущего периода (и
  пробного) или с сегодняшнего дня; повторное уведомление того же платежа ничего не меняет. Автосписаний нет:
  письмо «оплата получена», за 3 дня до конца — «тариф заканчивается» (API проверяет каждый час,
  `python -m app send-reminders` — сразу). История оплат — на «Тариф и оплата», все платежи — во вкладке «Платежи»
  админки. Без провайдера (`none`) всё как раньше: «Pro» по заявке. `PAYMENT_PROVIDER=test` — тестовая страница
  «Оплатить / Отменить» для разработки. **cisPay** (`PAYMENT_PROVIDER=cispay`, `backend/app/cispay.py`): счёт в
  копейках с `order_id` = id нашего платежа, покупатель платит картой или по СБП на странице cisPay и
  возвращается на `SITE_URL/billing?payment=…`; результат приходит вебхуком с подписью HMAC-SHA256 (ключ —
  `CISPAY_API_KEY`), а пока страница возврата ждёт, API сам спрашивает статус у cisPay; кроме того, раз в 5 минут
  API сверяет с провайдером все ещё ожидающие платежи за последние двое суток — потерянный вебхук и закрытая
  вкладка не подвешивают оплату. Письмо «оплата получена» уходит после ответа, вебхук не ждёт почту. `FAILED`/`EXPIRED` — платёж отменён (оплата после повторной попытки на странице cisPay
  всё равно засчитается), `REFUNDED` — только в журнал: тариф после возврата решает админ. Платежи песочницы
  (`is_sandbox`) не засчитываются, кроме `CISPAY_SANDBOX=true` в разработке. Другой провайдер — ещё один класс в
  `billing.py` (`create()`, `check()`) и вебхук, который проверяет подпись и вызывает `settle()`.

  каждого кузова, кнопка «+ Прицеп» (до 3 кузовов). При изменении кузова грузы едут вместе с ним
  (привязка к передней стенке), грузы удалённого кузова переезжают на док.
- **Несколько машин** (до 10): «+ Машина» с выбором шаблона ставит новую машину рядом с остальными у той же
  рампы. Переключение — чипы в карточке «Транспорт» или клик по табличке с именем над кабиной: камера
  переезжает к машине, карточка, статистика, новые грузы и автозагрузка относятся к ней; выбор груза в другой
  машине делает активной её. У машины есть имя, её можно убрать (грузы переезжают на док, отмена — Ctrl+Z).
  **Зона накопления**: «Общая» — одна платформа вдоль всех машин, машины стоят плотно (5,2 м между осями), груз
  удобно перекладывать из машины в машину; «У каждой своя» — отдельный док за каждой машиной, у каждой свои грузы.
  При переключении грузы остаются у своей машины, а то, что не помещается рядом, переставляется на свободные места.
- **Грузы**: ввод Ширина / Высота / Длина, количество, название, типовые грузы (европаллета, финпаллета, IBC…),
  список с размерами и статусом («В кузове» / имя машины / «Док» / «За габаритами»), инспектор выбранного груза
  (размеры, название, цвет), поворот на 90°, дублирование, удаление.
- **Кантование** (включается переключателем «Кантовать» в инспекторе или в меню «Вид»): поворот на 90° вокруг любой
  оси — X (вдоль машины, груз ложится на бок), Y (вертикаль, как раньше) и Z (поперёк, груз встаёт на торец), всего
  шесть положений. Выключено — только вокруг вертикали. Автозагрузка кантованный груз не переворачивает обратно,
  а сама грузы не кантует. Повороты на произвольный угол не делаются: физика работает с прямоугольными объёмами.
- **Прозрачность грузов** (кнопка с глазом над сценой или меню «Вид»): «Перед выбранным» — грузы между камерой и
  выбранным грузом становятся полупрозрачными (по умолчанию); «Все загораживающие» — всё, за чем спрятаны другие
  грузы (рентген загрузки); «Все грузы» — кроме выбранного; «Выключена». Плотность — ползунком. Тень прозрачного
  груза бледнеет вместе с ним (не пропадает рывком), контур остаётся виден, переход плавный; нажатие на прозрачный
  груз берёт тот, что виден за ним.
  С несколькими машинами грузы соседних машин, закрывающие активную, прозрачны всегда (кроме «Выключена»).
- **Сцена**: размерные линии «как на чертеже» (подписи прячутся, если не помещаются), линия длины груза
  у каждого кузова — на земле сбоку от машины (от передней стенки до самого заднего груза = LDM, следит и за
  перетаскиванием), номера на грузах, размеры выбранного груза, виды 3D / сверху / сбоку / сзади, «показать всё»,
  фиксация камеры. Камера летает на WASD (вдоль земли, с Shift — быстрее).
- **Режимы отображения** (кнопка с названием режима на панели камеры или меню «Вид»): пресеты «Стандарт», «Только рёбра» (кузов — одни рёбра, без стенок,
  стоек и разметки пола; размеры остаются), «Чертёж» (ещё без кабины, колёс и теней) и «Для клиента» (без
  размеров, линеек и номеров). «Все настройки отображения…» — окно с живым примером грузовика: каждая опция
  отдельно (стенки и их прозрачность, стойки, разметка пола, кабина и колёса, тени, размеры, линейка длины
  загрузки, номера, прозрачность грузов, единицы). Пресеты — `src/editor/displayPresets.ts`, настройки — в
  аккаунте, как остальные.
- **Фиксация грузов** (рука на панели камеры или меню «Вид»): режим просмотра — грузы не двигаются и не
  меняют размер мышью, нажатие на груз крутит камеру, тап выделяет. Клавиатура работает как обычно.
- **Зафиксировать груз** (замок в инспекторе, клавиша `L`, снять — тоже по бейджу «Зафиксирован» на грузе):
  груз не двигается, не поворачивается и не меняет размер, как и грузы, на которых он стоит; автозагрузка его
  не трогает (и при «переложить всё»). На номере груза — замок.
- **«Мостик» из грузов**: при перетаскивании груз держит свой ярус — едет по полу и заезжает под груз,
  лежащий на других (если влезает), а на груз поднимается, только когда на полу места нет. Если у груза есть
  другой ярус на том же месте, на нём появляются кнопки «Наверх» / «Вниз» (и клавиши PgUp / PgDn — в том
  числе во время перетаскивания).
- **«Подсвечивать выходы за грани»**: части груза за стенками/потолком кузова подсвечиваются красным
  объёмом, рёбра груза краснеют; счётчик в шапке и статистике.
- **Статистика**: заполнение кузова по объёму, LDM (занятые погонные метры от передней стенки), количество
  грузов в кузове / на доке / за габаритами.
- **Отмена/повтор** (Ctrl+Z / Ctrl+Y), экспорт плана в JSON и замена содержимого из JSON (отменяемо).
- **Экспорт в PDF** («Файл» → «Экспорт в PDF…», по выбранной машине или по всем — каждая с новой страницы):
  план загрузки для водителя и склада на A4 (альбомная или
  книжная) — виды сверху и сбоку с номерами грузов (ортографические, как чертёж, с линейками, или
  перспективные), список мест (одинаковые грузы одной строкой, что осталось на доке или вышло за габариты —
  цветом), итог по кузову (масса, места, объём, площадь пола, длина/ширина/высота: занято, максимум, остаток) и
  развесовка (центр тяжести против нормы), нагрузка на оси (каждая опора: нагрузка, на ось, из неё груз,
  допустимо, оценка; перегруз — ещё и строкой на первой странице). Режим «Пошаговая инструкция» добавляет порядок загрузки с выбранной
  стороны (сзади, сбоку справа/слева, сверху): груз ставится после того, на чём стоит, и после того, что дальше
  от проёма в его ряду; по картинке на шаг, уже загруженное — серым. PDF собирается в браузере (pdfmake, шрифт
  Roboto), библиотека подгружается только при экспорте.
- **Вес и грузоподъёмность**: вес у каждого груза (кг, у типовых грузов — типичный), грузоподъёмность у
  кузова (т, у шаблонов транспорта — своя). В статистике — вес кузова из грузоподъёмности и центр тяжести
  груза (ЦТ, % длины от передней стенки): зелёный — в безопасной зоне, жёлтый — нет.
- **Нагрузка на оси**: для каждой машины — передняя и ведущая ось тягача, седло, оси полуприцепа; передняя и
  задние оси грузовика; оси прицепа или сцепка прицепа с центральной осью (её вес переходит на заднюю часть
  машины впереди). Каждый кузов — балка на двух опорах, груз весит в центре своего места, группа осей делит
  нагрузку поровну (`core/chassis.ts`). Блок «Нагрузка на оси» в строке статистики (у каждой оси нагрузка,
  допустимое и полоска; красный — перегруз или ось отрывается, жёлтый — рулевой оси меньше 20% массы) и строка «Нагрузка на оси» в карточке «Транспорт»
  открывают окно: вид сбоку с нагрузками под колёсами и таблица опор. Позиция, число осей, порожняя масса и
  допустимая нагрузка сначала как у машины шаблона (`CargoBody.chassisModel`: еврофура, мега и реф с тягачом 4×2,
  сцепка, контейнеровозы 20′ и 40′, грузовик 18 т, фургон 7 т; еврофура — те же цифры, что в калькуляторе) или
  типичные для своего кузова; их можно заменить своими — в схеме хранятся только изменённые (`CargoBody.chassis`).
  Позиции — только где оси бывают: рулевая под кабиной, остальные под кузовом и не друг на друге. Колёса в 3D-сцене
  стоят там же, где оси в расчёте.
- **Автозагрузка** («Загрузить в кузов»): грузы с дока раскладываются в кузов сами — тяжёлые на пол и ближе к
  середине, лёгкие сверху (только когда на полу нет места, целиком на опоре), каждый ряд прижат к борту так,
  чтобы груз не перекашивало, грузоподъёмность не превышается. Перед применением — предпросмотр: сколько
  встанет, вес и центр тяжести по кузовам, что и почему останется на доке. Можно переложить заново и то, что
  уже в кузове. Отменяется одним Ctrl+Z.
- **Редактор**: шапка — назад к схемам, название (переименование по клику), статус сохранения, отмена/повтор,
  меню «Вид» (размерные линии, номера, выходы за грани, магниты, ручки, единицы), «Файл», справка, кнопка
  панели грузов. Над сценой — карточка «Транспорт» (шаблон, размеры и грузоподъёмность кузовов, «+ Прицеп»,
  сворачивается), камера и статистика; справа — плавающая панель грузов (новый груз, автозагрузка, список,
  инспектор выбранного), её можно скрыть; на телефоне она открывается шторкой.

## Управление (без переключения режимов)

| Действие | Мышь | Планшет |
|---|---|---|
| Вращение сцены | тянуть по пустому месту | один палец по фону |
| Перемещение груза | тянуть груз (стопка на нём едет вместе) | палец на грузе |
| Только этот груз, без стопки | Alt + тянуть | — |
| Без магнитов | держать Shift | — |
| Панорама / масштаб | ПКМ / колесо | два пальца |
| Изменить размер | тянуть стрелки на гранях выбранного груза | то же |
| Наверх / под «мостик» | «Наверх» / «Вниз» на грузе, PgUp / PgDn | кнопки на грузе (и вторым пальцем при перетаскивании) |
| Камера вперёд / вбок | W A S D (Shift — быстрее) | — |
| Только смотреть | «Фиксация грузов» (рука на панели камеры) | то же |
| Приблизить к грузу | двойной клик | двойной тап |

Клавиши для выбранного груза: `R` — поворот 90° вокруг вертикали, `X` / `Y` / `Z` — вокруг оси X / Y / Z (при
включённом кантовании), `Del` — удалить, `Ctrl+D` — дублировать,
стрелки — сдвиг на 1 см (Shift — 10 см) по направлению взгляда камеры, `PgUp` / `PgDn` — на груз над ним / под
него, `L` — зафиксировать / освободить, `F` — показать, `Esc` — отмена перетаскивания. `W` `A` `S` `D` двигают
камеру всегда.

### Как устроено контекстное взаимодействие

`InteractionManager` слушает `pointerdown` на контейнере канваса в фазе **capture**, то есть раньше
OrbitControls. Делается raycast: если под указателем груз (или ручка размера) — событие останавливается
(`stopPropagation`), камера его не видит, начинается перетаскивание; если пусто — событие уходит дальше в
OrbitControls и сцена вращается. Дополнительные пальцы во время перетаскивания игнорируются, а пальцы,
присоединившиеся к жесту камеры, остаются у камеры (щипок, панорама).

### Почему грузы не висят и не пересекаются

Высоту груза пользователь не задаёт. При перемещении группа ставится на высоту
`max(верх всех грузов под её основанием, 0)` — так она не может ни пересечь соседа, ни повиснуть.
После любого изменения выполняется `settle()` — проход «гравитации» снизу вверх, который гарантирует
отсутствие пересечений и висящих грузов для любого входного состояния (это проверяют тесты).
Магнит никогда не «запрыгивает» на соседа: вариант привязки принимается, только если не поднимает груз.

### Точки расширения

- **Поворот**: `Orientation` (`yaw` + `up` — какая своя сторона смотрит вверх) + `axisMap()` / `effectiveDims()` /
  `intrinsicDims()` / `rotate90()` в `core/orientation.ts` — все шесть положений с шагом 90° вокруг любой оси.
  Свободный угол потребует OBB-коллизий в `geometry.ts`/`physics.ts` — остальной код работает через `itemBox()`.
- **Изменение размеров на сцене**: уже работает push/pull граней (`core/resize.ts` + `scene/tools/ResizeTool.ts`):
  округление до 1 см, привязка к граням соседей и стенкам, упор в соседа, грузы сверху поднимаются гравитацией.
  Ввод точного значения с клавиатуры во время жеста — следующий шаг.
- **Новые жесты** (рамка множественного выбора, рулетка): реализовать `Tool` и добавить ветку в
  `InteractionManager.createTool()`.
